# Bashment Product Requirements

## Product Objective

Build a SaaS platform that connects nightlife and culture discovery with event intelligence and promoter tools.

The product should help users discover relevant experiences while giving promoters and venues better visibility into event activity, attendance, engagement, and performance.

---

## Target Users

### Patrons

People looking to discover nightlife and cultural experiences and understand what is happening around them.

### Promoters

Event organizers who need tools to create and manage events and gain visibility into event activity and performance.

### Venues

Businesses seeking better visibility into event activity, attendance, and performance.

---

## Core Requirements

### 1. Event Discovery

Users should be able to discover nightlife and cultural events based on location and available event information.

### 2. Event Creation

Promoters should be able to create and manage event information through the platform.

### 3. Location-Based Experience

The platform should provide map-based functionality to help users understand where events and activity are occurring.

### 4. Event Activity

The platform should collect and display relevant activity signals associated with events.

### 5. Attendance Intelligence

The platform should collect information that can eventually support attendance estimation and forecasting.

### 6. Forecast Explanation

Forecasts should provide transparent explanations rather than presenting unexplained numbers.

### 7. Recommendations

The platform should progressively transform event and behavioral data into actionable recommendations.

### 8. Measurement

The platform should compare forecasts and recommendations against actual event outcomes.

### 9. Continuous Learning

Completed-event data and forecast-versus-actual results should inform future improvements to the intelligence layer.

---

## Intelligence Requirements

The intelligence layer follows:

**DATA → PREDICT → EXPLAIN → RECOMMEND → ACT → MEASURE → LEARN**

The initial forecasting approach should prioritize transparent statistical and baseline methods.

As sufficient completed-event data becomes available, the system can evolve toward more advanced machine learning approaches.

---

## Beta Requirements

The beta should prioritize:

- User acquisition
- Event data collection
- User feedback
- Promoter feedback
- Product validation
- Identification of useful event signals
- Forecast-versus-actual measurement

The beta is intended to establish the data foundation required for future intelligence capabilities.

---

## Product Success Measures

Initial measures should include:

- Beta user adoption
- Event creation and participation
- User engagement
- Data completeness
- User feedback
- Forecast availability
- Forecast accuracy
- Forecast-versus-actual performance
- Adoption of recommendations

---

## Product Principle

Bashment should prioritize **useful, explainable intelligence over opaque AI outputs**.

The product should improve through a continuous cycle of:

**BUILD → TEST → MEASURE → LEARN → IMPROVE**
